# Example run reports

Generated by the pipeline itself, unedited. All three use the fictional profile and postings in `examples/` and the deterministic mock model, so they show how the pipeline behaves, not a real model's writing. Token counts are estimates (characters / 4).

| Report | How it was produced |
|---|---|
| [demo-faults.md](demo-faults.md) | `pipeline run --profile examples/profile.json --criteria examples/criteria.json --source fixture:examples/jobs.json --model mock --faults demo --run-id example-demo-faults` |
| [token-budget.md](token-budget.md) | The same, without `--faults`, with `--token-budget 6000 --run-id example-token-budget` |
| [worker-crash.md](worker-crash.md) | `docker compose up -d worker`, then `pipeline run ... --model mock --mock-latency 4s --no-workers`, then `docker compose kill worker` about 6 s in (while the three writer steps were running), then `docker compose up -d worker` again. Re-rendered with `pipeline report <run-id> --render` once restart detection was added to the report. |
