# Example run reports

Generated by the pipeline itself, unedited. All use the fictional profile and postings in `examples/`. The first is a real local model. The other three use the deterministic mock model, so they show how the pipeline behaves, not a real model's writing, and their token counts are estimates (characters / 4).

| Report | How it was produced |
|---|---|
| [local-qwen3-4b.md](local-qwen3-4b.md) | `pipeline run --profile examples/profile.json --criteria examples/criteria.json --source fixture:examples/jobs.json --model ollama:qwen3:4b-instruct --concurrency 1 --step-timeout 20m --run-id example-local-qwen3-run2` on an M1 with Ollama. Re-rendered with `pipeline report <run-id> --render` after the effort label was dropped for local models. |
| [demo-faults.md](demo-faults.md) | `pipeline run --profile examples/profile.json --criteria examples/criteria.json --source fixture:examples/jobs.json --model mock --faults demo --run-id example-demo-faults` |
| [token-budget.md](token-budget.md) | The same, without `--faults`, with `--token-budget 6000 --run-id example-token-budget` |
| [worker-crash.md](worker-crash.md) | `docker compose up -d worker`, then `pipeline run ... --model mock --mock-latency 4s --no-workers`, then `docker compose kill worker` about 6 s in (while the three writer steps were running), then `docker compose up -d worker` again. Re-rendered with `pipeline report <run-id> --render` once restart detection was added to the report. |
